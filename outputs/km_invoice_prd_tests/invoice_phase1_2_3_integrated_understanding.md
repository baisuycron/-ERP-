# 发票一期、二期、三期需求整体理解

## 1. 总体定位

三期需求不是三个彼此独立的功能包，而是一条逐步完善的发票业务闭环：

- 一期：建立发票业务主流程。核心是买家发起开票申请，卖家处理开票/驳回，平台配置超时规则并查看发票数据，同时补齐 PC、小程序、供应商后台、平台后台和第三方接口的基础状态流转。
- 二期：提升批量与异步处理能力。核心是买家侧导出/下载改为异步任务，小程序补齐批量申请/撤销能力，平台和卖家补齐发票待办，供应商批量导入改成异步任务。
- 三期：优化业务兼容性和展示颗粒度。核心是发票抬头可同时支持普票/专票并和店铺支持类型自动匹配，卖家/平台增加超时与上传/修改时间字段，支持单订单多张发票，订单详情从跳页改为抽屉，导出模板继续细化。

整体目标是把发票从“订单附属字段”升级成“有申请、处理、状态、导出、任务、待办、接口、详情展示”的完整业务域。

## 2. 核心状态模型

买家侧开票状态：

- 待申请：订单已完成、售后非售后中、未提交过开票申请，代表可申请开票。
- 已申请：买家提交开票申请后进入该状态，卖家可驳回或确认开票。
- 已驳回：卖家驳回后进入该状态，可重新提交开票申请，可视为待申请的子状态。
- 已撤销：买家主动撤销后进入该状态，可重新提交开票申请，可视为待申请的子状态。
- 已开票：卖家确认开票后进入该状态。

卖家侧对应状态：

- 待开票：买家已申请，卖家待处理。
- 已驳回：卖家驳回。
- 已撤销：买家撤销。
- 已开票：卖家确认开票。

状态流转主链路：

```text
待申请 -> 已申请/待开票 -> 已开票
                     -> 已驳回 -> 可重新申请
                     -> 已撤销 -> 可重新申请
```

测试重点：

- 撤销/驳回后再次申请是否重置/保留正确字段。
- 卖家侧待开票数量角标、已驳回/已撤销页签数据是否随状态流转正确变化。
- 已驳回、已撤销在三期不应显示超时标签，剩余超时天数显示为 `-`。
- 开票状态必须在关键动作提交时二次校验，避免并发期间状态变化导致脏数据。

## 3. 一期需求理解

一期是基础发票体系建设。

### 买家 PC

新增或整合 `商家中心 > 发票管理`，包含：

- 可申请开票
- 已申请开票
- 已开具发票
- 发票抬头管理

可申请开票重点规则：

- 订单已完成且售后非售后中才可申请。
- 整单退款成功或订单所有 SKU 均退款成功不应出现在开票列表。
- 售后中订单不可选，不允许申请开票。
- 先货后款未还款订单不允许申请开票，按钮置灰或隐藏，并提示“未还款的先货后款订单不允许申请开票”。
- 批量申请需校验售后状态、开票状态、闪购门店是否关联发票抬头。
- 闪购门店为 `-` 的订单，需要买家手动选择发票抬头；未选择时报错。
- 申请成功生成唯一开票批次，订单开票状态变为已申请。
- 发票内容支持商品类别/商品明细，默认商品类别。
- 开票备注非必填，最多 100 字。
- 需要单独开票字段默认否，后续在修改、确认、导入、接口中都是重要校验字段。

已申请开票重点规则：

- 支持查看、修改开票信息、撤销申请、批量修改、批量撤销。
- 每次提交开票申请后只允许修改一次开票信息。
- 修改内容包括发票抬头、需要单独开票、发票内容、开票备注。
- 撤销成功后流转回可申请开票，状态为已撤销，可重新申请。
- 批量修改时，“请选择”代表本次不修改该项。
- 操作提交前需再次校验状态和售后状态。

已开具发票重点规则：

- 展示发票详情、发票号码、开票金额、开票时间、需要单独开票等。
- 支持下载发票文件。
- 导出初期按查询结果导出，后续二期调整为异步任务中心。

发票抬头管理重点规则：

- 支持按闪购门店、发票抬头查询。
- 新增收票人手机和收票人邮箱，手机和邮箱二选一。
- 手机格式需支持港澳台；邮箱需格式校验。
- 抬头信息在申请、修改、查看悬停信息中复用。

### 买家小程序

一期小程序主要补齐订单列表和发票详情能力：

- 订单列表/查看发票增加发票状态展示。
- 申请开票时直接展示发票信息预览。
- 支持发票内容、需要单独开票、开票备注。
- 已驳回、已撤销状态下可重新申请。
- 已申请未开票时支持修改发票信息。
- 我的发票抬头新增收票人手机/邮箱，与 PC 校验一致。

### 卖家侧

卖家侧是处理中心：

- 首页增加发票待办事项：待开票、即将超时、超时未开票。
- 发票管理增加全部、待开票、已驳回、已撤销、已完成/已开票页签。
- 待开票支持确认开票、批量确认开票、驳回、批量驳回。
- 已驳回/已撤销页签不需要复选框和批量操作。
- 发票详情需展示开票状态、需要单独开票、发票类型、发票内容、申请时间、发票号码、金额、开票时间、抬头信息、开票备注。

批量确认/批量修改开票的核心校验顺序：

1. 开票状态。
2. 发票抬头 + 纳税人识别号。
3. 需要单独开票。
4. 发票类型。
5. 发票内容。

需要单独开票为“是”的订单不允许与其他订单合并开同一张发票。

### 平台侧

平台侧有两块：

- 交易设置：配置开票处理时限 X、超时前预警天数 N，要求 `0 < N < X`。
- 店铺/发票管理：查看发票列表和详情，但不承担卖家的批量确认/驳回操作。

平台发票列表应补充店铺信息，平台导出也要带店铺信息和需要单独开票字段。

### 供应商批量导入与接口

一期批量导入：

- 上传 ZIP，ZIP 内包含一个 XLSX 模板和发票 PDF。
- PDF 按“发票号码.PDF”命名，系统用 XLSX 中发票号码匹配同名 PDF。
- XLSX 大小 1M，ZIP 初期限制 20M。
- 同一张发票关联多笔订单时，被关联订单不允许部分失败。
- 导入失败不生成发票记录，不更新订单开票状态。
- 后续补充增加需要单独开票、发票内容字段及校验。

第三方开票 API：

- 订单下载接口增加发票抬头类型。
- 发票订单下载接口支持开票批次查询，返回是否单独开票、开票批次、开票状态。
- 同步开票接口要求订单已完成、售后非售后中、开票状态不能是已驳回/已撤销。
- 需要单独开票为是的订单不允许和其他订单共用一个发票号码。

## 4. 二期需求理解

二期是在一期基础上补齐“异步任务化”和“小程序批量能力”。

### 买家 PC：任务中心与异步导出/下载

二期早期提过发票管理页内“导出记录”，但 2026-05-25/2026-05-26 更新后，统一改为顶部任务中心。

当前应按最新口径理解：

- 买家登录成功并进入商家中心后，顶部功能导航区展示任务中心。
- 非商家中心页面不展示任务中心。
- 可申请开票、已申请开票、已开具发票的数据导出都改为异步任务。
- 已开具发票支持批量下载发票，生成异步下载任务。
- 任务中心仅能查看、下载当前账号自己的任务。
- 执行成功才允许下载。
- 关闭任务中心弹窗不等于取消导出/下载任务。
- 刷新按钮刷新任务列表和状态。

批量下载发票：

- 未选中订单点击批量下载，提示请先选择。
- 最多选择 200 条，限制随分页数据选项动态变化。
- 生成 ZIP 压缩包，命名为 `订单发票文件yyyy-MM-dd_HH_mm`。
- 压缩包内包含发票 PDF 和对应订单的已开具发票导出 Excel。
- PDF 用发票号码命名。
- 任务成功后相关订单下载状态更新为已下载。

发票下载状态：

- 二期文档中 PC 侧存在已下载/未下载/全部逻辑。
- 小程序侧后续更新中去掉生成下载链接和发票下载状态。
- 测试时需按端区分，避免把小程序旧逻辑当作现行逻辑。

### 小程序：发票管理批量化

小程序入口从“我的发票抬头”升级为“发票管理”，补齐 PC 已有能力：

- 可申请开票：批量申请、编辑、移除、本页全选、选择发票抬头、设置发票内容/备注。
- 已申请开票：支持单选/多选、撤销、修改、筛选；暂不做单个订单详情中的修改/撤销，统一通过选中订单操作。
- 已开具发票：支持筛选、预览、订单展开/折叠；去掉小程序端生成下载链接。
- 订单 > 查看发票：已提交但卖家未开票的订单增加撤销申请，确认时需再次校验售后状态和开票状态。

小程序筛选重点：

- 闪购门店多选，多个门店展示第一个 +N。
- 下单账号多选，但“全部”不能和具体账号同时多选。
- 售后状态、需要单独开票等按页签差异展示。
- 部分搜索项在 2026-05-26 更新中被去掉，测试用例应以更新后的口径为准。

### 平台/卖家：发票待办

平台侧待办：

- 待办分类增加发票管理。
- 标题包括即将超时的开票申请提醒、已超时的开票申请提醒。
- 系统每天 0 点按店铺自动生成待办。
- 前一日 23:59:59 前无对应数据则不生成。
- 初始状态待处理，创建时间为生成时间，完成时间为 `-`。
- 平台支持查看、催办、删除。
- 催办次数达到 3 次显示“急”。
- 删除后平台侧和供应商侧同步删除。
- 处理进度随订单开票状态变更动态减少，全部已开票后待办状态变为已完成并记录完成时间。
- 未处理的历史待办，次日可再次生成新待办，进度相互关联到订单状态。

卖家侧待办：

- 首页/待办管理增加发票管理分类。
- 支持查看待办详情。
- 详情增加去处理入口。
- 已超时待办跳转发票管理并筛选超时。
- 即将超时待办跳转发票管理并筛选即将超时。
- 卖家侧不支持催办和删除。

### 卖家/平台任务中心与异步导入

平台侧、供应商侧原右上角导出记录改造为任务中心：

- TAB 1：导出/下载任务。
- TAB 2：导入任务。
- 导入任务目前主要用于批量导入发票。
- 导入任务展示导入成功 X 条、失败 N 条。
- 只能查看、下载自己账号的导入数据。

供应商批量导入二期变化：

- 从同步导入改成异步导入。
- 上传 ZIP，XLSX 限制 1M，ZIP 限制升级为 200M。
- ZIP 内只允许存在一个 XLSX。
- 导入后在任务中心查看进度和结果。
- 同一张发票关联多笔订单时仍不允许部分失败。

### 其它优化

- 平台和供应商导出增加驳回原因字段，位置在开票状态与订单状态之间。
- 平台和供应商列表/查询条件增加订单状态，列设置同步增加。
- 买家侧订单页面增加温馨提示。

## 5. 三期需求理解

三期是基于前两期做兼容性、可视化和字段口径优化。

### 买家：发票抬头支持多类型

三期解决的核心痛点是：原来一个发票抬头只能选一种发票类型，店铺不支持时买家只能删掉重建。

新规则：

- 抬头类型与发票类型位置调整。
- 抬头类型为企业时，发票类型展示电子普通发票和电子增值税专用发票。
- 企业抬头至少选择一种发票类型，也可两种都选。
- 新增抬头默认企业，并默认勾选电子普通发票。
- 仅勾选普票时展示普票信息。
- 仅勾选专票时展示专票信息。
- 两种都勾选时展示专票信息。
- 抬头类型为个人时，只展示电子普通发票，默认选中且不可调整。

### 买家：申请开票类型匹配

提交开票申请时，系统按发票抬头勾选类型和店铺支持类型匹配：

| 抬头勾选类型 | 店铺支持类型 | 是否可提交 | 实际开票类型 |
| --- | --- | --- | --- |
| 仅普票 | 仅普票 | 是 | 普票 |
| 仅普票 | 仅专票 | 否 | - |
| 仅普票 | 同时支持 | 是 | 普票 |
| 仅专票 | 仅普票 | 否 | - |
| 仅专票 | 仅专票 | 是 | 专票 |
| 仅专票 | 同时支持 | 是 | 专票 |
| 两种均选 | 仅普票 | 是 | 普票 |
| 两种均选 | 仅专票 | 是 | 专票 |
| 两种均选 | 同时支持 | 是 | 专票 |

关键口径：

- 无可匹配类型时不可提交，并提示买家调整发票抬头。
- 只有一种可匹配类型时按该类型提交。
- 普票和专票都可匹配时默认按专票提交。
- 错误文案右侧有“去调整”。
- 点击去调整后在当前页面弹出发票抬头编辑页。
- 保存成功后回到批量申请开票弹窗，并重新校验同一批次中引用同一抬头的订单。
- 校验通过的订单清除错误文案，其他异常继续保留。
- 在申请页内编辑抬头成功后，发票抬头管理页也必须同步更新。
- PC 和小程序逻辑一致。

申请页面还新增：

- 全部订单、异常订单页签。
- 异常订单数量标识。
- 店铺信息。
- 店铺可开类型。
- 联系店铺客服图标。

### 买家：多张发票展示

PC：

- 已开具发票列表中，订单存在 2 张及以上发票时，发票号码右侧展示“更多”。
- 鼠标悬停更多展示全部发票号码。
- 发票详情支持多张发票。
- 订单页面查看发票同理。

小程序：

- 发票管理已开具发票页和订单查看发票页，存在多张发票时展示更多。
- 点击更多进入发票列表页。
- 发票列表页左侧展示订单号，右侧展示发票张数合计。
- 展示全部发票号码，点击预览沿用现有预览逻辑。
- 返回时回到原入口页面。

发票详情统一口径：

- 发票张数 = 上传发票合计。
- 开票金额（含税）合计 = 发票明细含税金额求和。
- 开票金额（不含税）合计 = 发票明细不含税金额求和。
- 下载全部发票为异步下载。
- 压缩包名称为订单号。
- 包内发票文件名为对应发票号码。

### 卖家：列表字段和交互优化

状态/字段：

- 已驳回订单不再显示超时标签。
- 发票管理增加开票超时时间、剩余超时天数、发票上传时间、发票修改时间。
- 新字段列设置同步增加，相关字段导出同步增加。

字段口径：

- 开票超时时间 = 开票申请提交成功时间 + 平台配置的开票处理时长，按 `10 × 24小时` 计算，格式 `YYYY-MM-DD HH:mm:ss`。
- 剩余超时天数 = 开票超时时间 - 当前时间。
- 仅待开票显示倒计时；已驳回、已撤销、已开票显示 `-`。
- 差值大于等于 0 显示“剩余X天X小时X分X秒”。
- 差值小于 0 显示“超时X天X小时X分X秒”。
- 发票上传时间 = 订单首次确认开票成功时间，Open API 同理。
- 发票修改时间 = 最新一次修改开票成功时间，Open API 同理。
- 修改开票只更新发票修改时间，不能影响发票上传时间。

交互：

- 买家账号列增加联系买家入口，点击后跳转客服 > 在线客服 > 该买家会话。
- 确认开票、批量确认开票、批量导入发票添加文件后显示真实文件名。
- 点击订单号不再跳转新页面，改为当前页面右侧订单详情抽屉。
- 抽屉可点 X 或左侧遮罩关闭。
- 抽屉内容与现有订单详情保持一致。
- 勾选订单后打开/关闭订单详情，原选中态必须保持。

### 卖家：多张发票上传与导入

确认开票、批量确认开票、修改发票：

- 支持上传多张发票，最多 5 张。
- 添加发票文件默认筛选 PDF。
- 回显每张发票文件。
- OCR 识别发票号码、开票时间、含税金额、不含税金额，且允许手动修改。
- 本次发票张数、含税合计、不含税合计按明细计算。
- 超过 5 张时仅取前 5 张，按添加顺序。
- 替换文件仅支持添加单张。
- 删除发票行后汇总同步更新。
- 修改发票时回显此前上传和录入的发票信息。
- Open API 同步支持多张发票。

批量导入发票：

- 从一笔订单一张发票调整为一笔订单最多 5 张发票。
- 同一发票号码不能被不同订单关联的逻辑保持不变。
- 同一订单超过 5 张时，该订单导入失败。
- 失败文档原因需记录：`一笔订单最多只能关联五张发票（XXX，XXX，XXX，XXX，XXX，XXX），请检查`。
- 失败原因中要完整展示该订单关联的所有发票号码。

卖家发票展示与导出：

- 列表多发票时展示更多，悬停展示全部号码。
- 发票详情支持多张发票，单张时只展示一行。
- 下载全部发票异步打包，包名订单号，文件名发票号码。
- 导出查询结果中发票号码支持多个号码导出，使用英文分号分割。
- 历史操作同步展示多个发票号码。
- 新增导出订单明细。
- 原导出查询结果改名为导出商品明细。
- 订单明细和商品明细均增加开票超时时间、发票上传时间、发票修改时间。

### 平台侧三期

平台侧与卖家侧共享大部分查看口径：

- 已驳回不显示超时标签。
- 增加开票超时时间、剩余超时天数、发票上传时间、发票修改时间。
- 点击订单号改为当前页面右侧抽屉。
- 发票号码支持多张更多展示。
- 发票详情支持多张发票和下载全部。
- 导出查询结果中多发票号码用英文分号分割。
- 历史操作同步展示多发票号码。
- 导出增加开票超时时间、发票上传时间、发票修改时间。

平台侧区别：

- 主要是查看、导出、历史操作，不承担卖家的确认/修改/批量导入操作。
- 字段口径要与卖家一致，但权限边界不能混淆。

## 6. 三期叠加后的统一业务主线

统一链路可以这样理解：

1. 平台配置开票处理时限和预警规则。
2. 买家维护发票抬头，三期后一个企业抬头可支持普票、专票或两者。
3. 买家从 PC 或小程序选择可申请订单提交开票申请。
4. 系统校验订单状态、售后状态、先货后款还款状态、店铺状态、发票抬头、店铺支持开票类型。
5. 提交成功生成开票批次，订单进入已申请/待开票。
6. 卖家在发票管理或待办入口处理，支持确认开票、批量确认、驳回、批量驳回、修改、批量导入。
7. 卖家确认后订单进入已开票，三期支持单订单最多 5 张发票。
8. 买家、卖家、平台三端展示同一开票事实。
9. 导出/下载/导入逐步异步化，通过任务中心查看状态和结果。
10. 超时、即将超时通过平台配置、卖家/平台字段、待办任务共同呈现。

## 7. 测试设计时的高风险点

建议后续测试用例重点围绕这些风险做覆盖：

- 状态并发：申请、修改、撤销、驳回、确认开票时，订单/售后/开票状态在操作期间发生变化。
- 资格规则：售后中、整单退款、先货后款未还款、店铺关闭/冻结、闪购门店为 `-`。
- 抬头匹配：抬头支持类型和店铺支持类型 3×3 矩阵，尤其“双方均可匹配默认专票”。
- 抬头同步：申请页内去调整后，同一批次引用同一抬头的订单重校验，以及发票抬头管理页同步。
- 单独开票：批量确认、批量修改、导入、API 中均要校验。
- 批量操作：批量申请、批量修改、批量撤销、批量确认、批量驳回、跨页选择、未选提示。
- 多发票：最多 5 张、超过 5 张、替换单张、删除、金额合计、下载压缩包、导出分号、历史操作。
- 异步任务：任务中心入口权限、任务状态刷新、关闭不取消、成功才下载、失败结果可查。
- 批量导入：ZIP 结构、XLSX 数量、文件大小、PDF 命名、发票号匹配、同票号多订单、超过 5 张失败文档。
- 待办任务：0 点生成、重复生成、进度动态减少、全部处理后完成、平台催办/删除和卖家权限差异。
- 字段口径：开票超时时间、剩余超时天数、上传时间、修改时间，尤其修改发票不能改首次上传时间。
- 导出模板：一期/二期/三期多次调整，需按最新口径区分买家任务中心、卖家订单/商品明细、平台导出字段。

## 8. 当前理解结论

如果后续要做全量测试用例，建议不要按“一期、二期、三期”机械分文件执行，而应按业务域合并：

- 基础状态与资格规则。
- 买家发票管理 PC。
- 买家小程序发票管理。
- 发票抬头管理与抬头类型匹配。
- 卖家发票管理与开票处理。
- 平台发票管理与配置。
- 任务中心、异步导出/下载/导入。
- 批量导入发票。
- 多张发票。
- 待办任务。
- 第三方/Open API。
- 导出模板与数据一致性。

这样能避免一期旧入口和二期/三期新口径混在一起，也更适合后续做一套“最终态”的可执行测试用例。
